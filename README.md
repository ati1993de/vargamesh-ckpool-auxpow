# VargaMesh CKPool AuxPoW — fixed 1% BTC fee

Bitcoin-parent / VargaMesh-child SHA-256d merged mining, built on CKPool.

## Fee policy (mandatory in this fork)

| Chain | Fee | Developer address | Applied where |
|---|---:|---|---|
| **Bitcoin (BTC)** | **1.00%** | `bc1qdw2puj3g4ypqyxql7dy3jw2f29u5q7fkvd584m` | Parent BTC coinbase output |
| **VargaMesh (VMESH)** | **1.00%** | `vm1qsfsgj70pdv86nguvexzvsflmcknz4lrsj87wx9` | Child VMESH coinbase output generated by the companion bridge |

Each fee is taken **only when its respective chain's block is found**.
BTC-only blocks do not generate VMESH fee payments, and VMESH-only blocks
do not generate BTC fee payments. Both use integer base-unit arithmetic:
`floor(coinbasevalue * 100 / 10000)` goes to the respective developer
address; the remainder pays the miner/pool address. `coinbasevalue` includes
subsidy and transaction fees.

### BTC enforcement details

- `src/fixed_fee.h` defines the **hard-coded BTC recipient and 100 basis points**.
- `src/ckpool.c` sets them at startup and ignores legacy `donrate`,
  `donaddress` and `donation` configuration values.
- `src/stratifier.c` fails closed if the BTC fee address cannot be validated
  or the fee policy changes, and creates the actual coinbase output.
- Works for normal directly generated BTC jobs and `ckpool -B` solo-address
  jobs. Proxy, passthrough, remote and redirector modes are intentionally
  refused because they can forward upstream work without this fee.
- **BTC mainnet only**: testnet/regtest address validation is expected to fail
  for the fixed `bc1...` recipient.
- No miner username, Stratum password, JSON, environment variable or CLI
  argument can disable or redirect the 1% fee in this unmodified build.

### VMESH enforcement details

The child fee **cannot be implemented in this CKPool binary alone**:
CKPool receives only the child hash and creates the Bitcoin parent job.
The separate [VargaMesh AuxPoW Bridge](https://github.com/ati1993de/vargamesh-auxpow-bridge)
builds the VMESH coinbase and verifies its 1% fee again in the VMESH submitter.
**Deploy the matching updated bridge** to enforce both currencies. This repo
alone does *not* protect child payouts made by a different bridge.

**Limits:** this is not blockchain consensus or cryptographic anti-tamper.
Anyone can modify a fork of public GPL code or mine through a different pool.
The fixed policy applies to unmodified builds of these two components. It is
not a protocol-level fee on independent VMESH/BTC miners.

## Integration

Parent chain: Bitcoin. Child chain: VMESH. Algorithm: SHA-256d. Mining:
AuxPoW merged mining.

VMESH-specific CKPool config keys:

- `vmeshmerged`
- `vmeshstate`
- `vmeshcanddir`
- `vmeshsubmit`

The example `examples/ckpool-vmesh.example.conf` contains no developer
fee override. Configure the miner/pool `btcaddress` and RPC credentials
separately from the mandatory fee address. Use `-B` to pay a valid BTC
miner username in SOLO mode.

Tests: `cc -std=gnu11 -Wall -Wextra -Werror -Isrc tests/test_fixed_fee.c -o /tmp/test-fixed-fee && /tmp/test-fixed-fee`
and CI build on GitHub Actions.

This public repo does not ship the private Varga-Tech production deployment,
per-miner VMESH SOLO binding, secrets, RPC passwords, cookies, or production
infrastructure paths. Verify coinbase outputs on both chains on a staging node
before rolling out to production.
